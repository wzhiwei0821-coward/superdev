# PostgreSQL 方言（适用 PostgreSQL 12+ / openGauss / GaussDB）

> 本文件供 `/mpdev-init` 读取，也适用于 PG 分支：openGauss、GaussDB（华为）、AWS RDS PG、阿里云 PolarDB for PG。

<!-- BLOCK:DB_CONFIG -->
- **主库**：PostgreSQL 12+ / openGauss / GaussDB（PG 兼容）
- **字符集**：`UTF8`（建库时固定，后期无法改）
- **Schema 组织**：默认 `public`；大型项目可用多 schema 做命名空间隔离
- **ORM**：Java 用 MyBatis / JPA；Python 用 SQLAlchemy / Django ORM；Go 用 GORM
- **命名**：表名 `snake_case` 单数；字段 `snake_case`
- **主键**：推荐 `BIGINT GENERATED BY DEFAULT AS IDENTITY` (SQL 标准语法) 或 `BIGSERIAL`（老写法）
- **审计字段**：`created_at` / `updated_at` / `deleted_at`
- **迁移目录**：`sql/V{n}__{desc}.sql`
<!-- /BLOCK:DB_CONFIG -->

<!-- BLOCK:DIALECT_CAVEATS -->
- ✅ 大多数 ALTER 操作默认**不锁表**（in-place），优于 MySQL
- ✅ `CREATE INDEX CONCURRENTLY` 完全不阻塞读写（但不能在事务内）
- ✅ PG 11+：`ADD COLUMN NOT NULL DEFAULT` 不再重写整表（fast add）
- ⚠️ `VARCHAR` 和 `TEXT` 在 PG 里**性能几乎相同**，不用刻意选 VARCHAR（Oracle/MySQL 的经验不适用）
- ⚠️ `TIMESTAMP` vs `TIMESTAMPTZ`：默认用 `TIMESTAMPTZ`（带时区，避免踩坑）
- ⚠️ 无自增列概念，用 `IDENTITY` 或 `SERIAL`（SERIAL 本质是 SEQUENCE + DEFAULT）
- ⚠️ 大小写敏感：`CREATE TABLE Users` 等价于 `CREATE TABLE users`；加双引号才保留大小写 `"Users"`
- 🌟 独有能力：JSONB（索引化 JSON）、GIN/GiST/BRIN 索引、部分索引、CTE、窗口函数
<!-- /BLOCK:DIALECT_CAVEATS -->

<!-- BLOCK:TYPE_CHOICES -->
| 场景 | 推荐类型 | 备注 |
|------|---------|------|
| 字符串 | `VARCHAR(n)` 或 `TEXT` | 两者性能相同，VARCHAR 有长度校验 |
| 布尔 | `BOOLEAN` | PG 原生支持 |
| 小整数 | `SMALLINT` / `INTEGER` | |
| 金额 | `NUMERIC(18,2)` | DECIMAL 是别名 |
| 时间戳 | `TIMESTAMPTZ` | 强烈推荐带时区 |
| 全局 ID | `BIGINT GENERATED ... AS IDENTITY` | SQL 标准，优于 BIGSERIAL |
| JSON 数据 | `JSONB` | **非 JSON**，JSONB 可索引可压缩 |
| 数组 | `INT[]` / `TEXT[]` | PG 独有 |
| UUID | `UUID` | 原生类型，不用存字符串 |
| 枚举 | `CREATE TYPE ... AS ENUM (...)` | PG 原生 ENUM 比 MySQL 灵活（可 ADD VALUE） |
<!-- /BLOCK:TYPE_CHOICES -->

<!-- BLOCK:DDL_SAFETY -->
| DDL 操作 | 锁级别 | 安全度 |
|---------|--------|-------|
| ADD COLUMN NULL | ACCESS EXCLUSIVE（极短） | ✅ 毫秒级 |
| ADD COLUMN NOT NULL DEFAULT | ACCESS EXCLUSIVE（PG 11+ 瞬时） | ✅ 安全 |
| DROP COLUMN | ACCESS EXCLUSIVE（极短，不重写） | ✅ 安全 |
| ALTER COLUMN SET DATA TYPE（兼容类型） | SHARE | ⚠️ 大表慢 |
| ALTER COLUMN SET DATA TYPE（不兼容） | ACCESS EXCLUSIVE + 重写 | ❌ 大表危险 |
| **CREATE INDEX CONCURRENTLY** | SHARE UPDATE EXCLUSIVE | ✅ **不阻塞读写** |
| CREATE INDEX（普通） | SHARE | ⚠️ 阻塞写 |
| RENAME COLUMN | ACCESS EXCLUSIVE（瞬时） | ✅ |
| DROP COLUMN + CASCADE | ACCESS EXCLUSIVE | ⚠️ 检查依赖 |

**黄金法则**：所有生产索引都用 `CONCURRENTLY` 建。
<!-- /BLOCK:DDL_SAFETY -->

<!-- BLOCK:BIG_TABLE_TOOLS -->
- 表规模 > 1000w 行需规划：
  - **pg_repack**：在线重组表（去碎片、改表空间、改列类型）
  - **pg_squeeze**：类似 pg_repack 的自动化版本
  - **logical replication**：跨主表结构迁移（零停机重建）
- 本项目推荐: `pg_repack -d db -t table --jobs 4`
- 索引重建必用 `CONCURRENTLY`：`CREATE INDEX CONCURRENTLY idx_name ON t(col);`
<!-- /BLOCK:BIG_TABLE_TOOLS -->

<!-- BLOCK:INDEX_TYPES -->
- **B-Tree**：默认，等值+范围
- **Hash**：PG 10+ 才 crash-safe，通常还是 B-Tree 够用
- **GIN**（倒排）：jsonb / 数组 / 全文检索 `tsvector`
- **GiST**（通用搜索树）：几何、范围类型、近邻搜索
- **BRIN**（块范围索引）：超大表的有序列（时间序列、自增 ID）**索引极小**
- **SP-GiST**：分区树，稀疏 IP 前缀
- **部分索引**：`CREATE INDEX idx ON t(col) WHERE status=0;` —— 只索引活跃数据
- **覆盖索引**：`CREATE INDEX idx ON t(col1) INCLUDE (col2, col3);` —— 避免回表
- **表达式索引**：`CREATE INDEX idx ON t(LOWER(email));`
<!-- /BLOCK:INDEX_TYPES -->

<!-- BLOCK:BATCH_UPDATE -->
```sql
-- PostgreSQL 批量回填：用 CTE + UPDATE FROM
-- 一次事务处理一批，避免长事务

BEGIN;
WITH batch AS (
  SELECT id FROM tab
  WHERE col IS NULL
  ORDER BY id
  LIMIT 10000
  FOR UPDATE SKIP LOCKED  -- 并发友好
)
UPDATE tab SET col = 'new_value'
FROM batch
WHERE tab.id = batch.id;
COMMIT;
```

**大表优化**：考虑 `VACUUM ANALYZE tab;` 阶段性执行，避免膨胀。
<!-- /BLOCK:BATCH_UPDATE -->

<!-- BLOCK:AUDIT_FIELDS_SQL -->
```sql
-- PostgreSQL 审计字段（推荐 TIMESTAMPTZ）
created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
deleted_at TIMESTAMPTZ NULL
```

**updated_at 自动更新需 Trigger**（PG 无 MySQL 的 `ON UPDATE` 语法）：

```sql
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_tab_updated_at
  BEFORE UPDATE ON tab
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

**软删规范**：查询加 `WHERE deleted_at IS NULL`；配合部分索引：
```sql
CREATE INDEX idx_tab_active ON tab(id) WHERE deleted_at IS NULL;
```

8. **JSONB 优于 JSON** — 可索引可压缩
