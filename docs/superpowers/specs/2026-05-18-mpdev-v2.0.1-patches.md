# mpdev v2.0.1 — install BOM 自检 + migrate auto-clean flag

## 1. 问题陈述

v2.0.0 发布后 T42 audit / T36 实测发现 2 处可观察的真痛：

1. **install BOM bug (P0)**：v2.0.0 的 `mpdev/bin/install.ps1` / `mpdev/scripts/migrate-from-v1.ps1` 在中文 Windows 上无 BOM 时，PowerShell 默认按 GBK 解码 UTF-8 字节 → 中文 mojibake → 整个文件解析失败。表象是「install 跑了一半就挂」「migrate 完全启动不起来」。

2. **migrate QoL gap (P2)**：v1 项目迁到 v2 后，用户必须手动跑 4 行 `rm .claude/agents/{code-reviewer,integration-checker,acceptance-reviewer,doc-refresher}.md` 才能让 plugin 接管最新版的框架 agent。这是文档里的"推荐做法"，但每次迁一个项目都要敲 4 行，烦。

v2.0.0 的运行时已经通过手动加 BOM 修了 install.ps1 + migrate-from-v1.ps1（commit `b14914f`）。但**没有任何保护机制**防止：
- 同事 fork 后用 GBK / 无 BOM 编辑器（如 Windows 老版记事本）修改 .ps1
- 未来 PR 引入新的中文 .ps1 文件
- 我们自己 sed 修补时再次破坏 BOM

## 2. 设计目标

- 安装时**自动校验并修补** mpdev/ 内所有 .ps1 文件的 UTF-8 BOM，对任何 fork 形态都形成保护
- migrate 提供 opt-in flag 一步删 4 个框架 agent，减少老用户手工步骤
- 完全向后兼容：v2.0.0 用户 `/plugin update` 拉到 v2.0.1，无需任何额外操作
- 不改任何命令行为、报告格式、agent 调用约定

成功标准：
- 在故意删了 BOM 的 mpdev/ 上跑 install.sh / install.ps1，**输出能看到「补充了 N 个 .ps1」**且文件 BOM 回归
- 在 v1 项目跑 `migrate-from-v1.sh --auto-clean-framework-agents`，4 个框架 agent 文件被删除，其他文件不动
- v2.0.0 → v2.0.1 通过 `/plugin update` 直接生效，无破坏

## 5. #3 BOM 自检实现细节

### 5.1 install.sh

在现有 `Step 4/4` 引导块之后、`exit 0` 之前追加：

```bash
# ---- BOM 自检（v2.0.1+）----
# 修复 T42 audit bug：中文 Windows 上无 BOM 的 .ps1 会被 GBK 解码 → 整个文件挂
echo ""
echo "▶ Step 5/5: 校验 .ps1 文件 BOM"
fixed=0
# 用 find -print0 + while read -d '' 处理路径含空格的情况
while IFS= read -r -d '' f; do
  # 读前 3 字节
  bom=$(head -c 3 "$f" | od -An -tx1 | tr -d ' \n')
  if [ "$bom" != "efbbbf" ]; then
    # 缺 BOM，补上：写 EF BB BF + 原内容
    tmp="$(mktemp)"
    printf '\xef\xbb\xbf' > "$tmp"
    cat "$f" >> "$tmp"
    mv "$tmp" "$f"
    fixed=$((fixed + 1))
  fi
done < <(find "$TARGET" -name '*.ps1' -print0 2>/dev/null)
if [ $fixed -gt 0 ]; then
  echo "  ⚠️  补充了 $fixed 个 .ps1 文件的 UTF-8 BOM（可能源仓未加 BOM）"
else
  echo "  ✅ 所有 .ps1 文件 BOM 完整"
fi
```

同时把上方 `▶ Step 4/4: 在 Claude Code 内完成 plugin 注册` 改为 `▶ Step 4/5: ...`。

### 5.2 install.ps1

在文件末尾 `Write-Host "排错:    ..."` 之后追加：

```powershell
# BOM 自检（v2.0.1+）
$utf8Bom = New-Object System.Text.UTF8Encoding $true
$fixed = 0
foreach ($f in (Get-ChildItem -Path $Target -Recurse -Filter '*.ps1').FullName) {
    $bytes = [System.IO.File]::ReadAllBytes($f) | Select-Object -First 3
    $hasBom = ($bytes.Count -ge 3 -and $bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF)
    if (-not $hasBom) {
        $content = [System.IO.File]::ReadAllText($f, [System.Text.Encoding]::UTF8)
        [System.IO.File]::WriteAllText($f, $content, $utf8Bom)
        $fixed++
    }
}
if ($fixed -gt 0) {
    Write-Host "⚠️ 补充了 $fixed 个 .ps1 文件的 UTF-8 BOM（可能源仓未加 BOM）" -ForegroundColor Yellow
} else {
    Write-Host '✅ 所有 .ps1 文件 BOM 完整' -ForegroundColor Green
}
```

### 5.3 已知边界

- 仅扫 `.ps1` 文件（其他类型如 .sh 不需要 BOM，且 .sh 加 BOM 会破坏 shebang）
- 全部 .ps1 都扫，不区分是否含中文（实测：纯 ASCII .ps1 加 BOM 不影响 PowerShell 解析，所以无害）
- BOM 字节序列 `EF BB BF` 是 UTF-8 BOM 标准；BE/LE BOM（UTF-16）不应在 .ps1 出现，不处理

## 6. #4 --auto-clean-framework-agents flag 实现细节

### 6.1 migrate-from-v1.sh

文件**顶部**（`set -e` 之后、第一个 `if [ ! -d .claude ]` 之前）插入参数解析：

```bash
# ---- 参数 ----
AUTO_CLEAN=false
for arg in "$@"; do
  case $arg in
    --auto-clean-framework-agents) AUTO_CLEAN=true; shift ;;
    -h|--help)
      cat <<EOF
Usage: migrate-from-v1.sh [--auto-clean-framework-agents]

参数:
  --auto-clean-framework-agents  额外删除 4 个框架 agent（code-reviewer/
                                  integration-checker/acceptance-reviewer/
                                  doc-refresher），让 plugin 接管。
                                  默认不删（保护项目自定义）。
EOF
      exit 0 ;;
    *) echo "❌ 未知参数: $arg"; exit 1 ;;
  esac
done
```

Step 2/3 末尾、Step 3/3 开始之前插入 auto-clean 分支：

```bash
# 删 4 个框架 agent（仅当 --auto-clean-framework-agents）
if [ "$AUTO_CLEAN" = "true" ]; then
  echo ""
  echo "  --auto-clean-framework-agents: 移除 4 个框架 agent"
  cleaned=0
  for a in code-reviewer integration-checker acceptance-reviewer doc-refresher; do
    if [ -f ".claude/agents/$a.md" ]; then
      rm -f ".claude/agents/$a.md"
      echo "  - .claude/agents/$a.md (让 plugin 接管)"
      cleaned=$((cleaned + 1))
    fi
  done
  echo "  ✅ 已清理 $cleaned 个框架 agent"
fi
```

Step 3 末尾的"后续"提示文本条件化：

```bash
# Step 3 后的提示
if [ "$AUTO_CLEAN" = "true" ]; then
  echo "✅ 框架 agent 已被 plugin 接管。"
else
  # 现有 "推荐删 4 个框架 agent..." 提示
  echo "推荐删 4 个框架 agent（让 plugin 接管最新版本）:"
  echo "  rm .claude/agents/code-reviewer.md"
  # ... 现有内容
fi
```

```powershell
if ($AutoClean) {
    Write-Host ''
    Write-Host '  --auto-clean-framework-agents: 移除 4 个框架 agent' -ForegroundColor Cyan

    foreach ($a in 'code-reviewer','integration-checker','acceptance-reviewer','doc-refresher') {
        $p = ".claude/agents/$a.md"

            Remove-Item -Force $p
```

## 8. 验收剧本（7 项）

| # | 场景 | 操作 | 期望 |
|---|------|------|------|
| 1 | install.sh BOM 自检（无需补） | 装一个全新 mpdev/ | Step 5/5 输出 `✅ 所有 .ps1 文件 BOM 完整` |
| 2 | install.sh BOM 自检（需补） | 手工 `dd if=/dev/null of=...` 或 sed 删掉某 .ps1 的 BOM 前 3 字节，再跑 install.sh | Step 5/5 输出 `⚠️ 补充了 1 个 .ps1 文件的 UTF-8 BOM`，验证文件 BOM 回归 |
| 3 | install.ps1 BOM 自检 | 同上但在 Windows PowerShell 跑 | 输出 `Yellow` 警告 + BOM 回归 |
| 4 | migrate.sh 不带 flag | 沙盒 v1 项目跑 `bash migrate-from-v1.sh` | 保留所有 .claude/agents/* 包括 4 框架 agent；Step 3 仍打"推荐删 4 个框架 agent"提示 |
| 5 | migrate.sh `--auto-clean-framework-agents` | 沙盒 v1 项目跑 `bash migrate-from-v1.sh --auto-clean-framework-agents` | 4 框架 agent 文件被删；其他 agent（java-impl 等）/ mpdev-runs/ / .mpdev-* 保留；Step 3 改打 "✅ 框架 agent 已被 plugin 接管" |
| 6 | migrate.sh 未知参数 | `bash migrate-from-v1.sh --bogus` | 报错 `❌ 未知参数: --bogus`，exit 1 |
| 7 | migrate.sh `--help` | `bash migrate-from-v1.sh --help` | 输出 usage 段，exit 0 |

migrate.ps1 等价 4 场景（同 4-7）。

## 9. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|-----|------|------|
| BOM 自检在某些 shell 不兼容（如 BusyBox） | 低 | 中 | 用 POSIX 兼容的 `head -c 3` / `od -tx1` / `printf '\xef\xbb\xbf'`。已在 Git Bash for Windows 验证 |
| `find` 找到的 .ps1 路径含空格 | 低 | 低 | spec §5.1 已用 `find -print0 \| while read -r -d ''` 模式（POSIX 兼容）处理 |
| 用户已手工加 BOM（v2.0.0 之后），重新跑 install.sh 不应再补 | 低 | 低 | 检测前 3 字节是否 EF BB BF，已加 BOM 的会跳过。逻辑正确 |
| `--auto-clean-framework-agents` flag 名字太长 | 低 | 低 | 显式胜过简短。文档化 `--help` 让用户复制粘贴 |
| 老用户在 migrate 时不知道 flag 存在 | 中 | 低 | Step 3 默认提示文本里加一句"或下次跑 migrate 时加 `--auto-clean-framework-agents` flag 自动清理" |
