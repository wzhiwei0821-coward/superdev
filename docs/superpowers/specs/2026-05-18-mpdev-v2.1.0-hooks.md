# mpdev v2.1.0 — Hooks 接入设计

## 1. 问题陈述

v2.0.x 已稳定（plugin 安装 + 9 命令 + 4 框架 agent + runtime-probe）。但用户使用过程中有几处「手工成本」：

1. **每次会话开始**用户得手工告诉 Claude「这是个什么项目，跨哪些模块，技术栈是什么」——其实 `<project>/**/CLAUDE.md` 已经写了，可以自动注入
2. **用户描述需求时**可能不知道 mpdev 有现成命令，比如说"修个 NPE"时不知道要用 `/mpdev:fix`——可以基于关键词主动建议
3. **impl agent 报跨模块影响时**（输出 `cross_module_issue: <X>` 字段），主流程不一定立刻跟进——可以自动提示下一步

参考 mppm-master 的 hooks 设计（8 个 hook 覆盖 SessionStart / UserPromptSubmit / Stop 等事件，已在生产用），我们引入 **3 个轻量 hook** 解决上述场景。

## 2. 设计目标

- **零打扰**：所有 hook fail-silent，从不阻塞工作流；用户可一开关全禁（`MPDEV_NO_HOOKS=1`）
- **附加价值**：hook 给出的提示是建议性的，用户可忽略
- **可观察**：用户应该能看到 systemMessage 类提示（#2 关键词）；additionalContext 是给 Claude 的，用户不可见但 Claude 行为会变更
- **轻量**：3 个 hook 每个超时 ≤5s；hook 本身只读不写（不污染项目数据）
- **向后兼容**：v2.0.x 用户 `/plugin update` 拉到 v2.1.0，全部命令行为不变；hooks 自动启用

成功标准：
- 装好后 `/plugin list` 显示 hooks 已注册
- SessionStart：在含 CLAUDE.md 的项目内启动 Claude Code，Claude 第一句应感知到项目模块结构（不用用户解释）
- UserPromptSubmit：用户说"帮我修个 bug" → 显示 `💡 检测到 /mpdev:fix 相关关键词…` 类提示
- SubagentStop：impl agent 输出含 `cross_module_issue` 时，下一句 Claude 应主动提"另一模块也要改"
- `MPDEV_NO_HOOKS=1 claude` 启动后所有 hook 静默

## 3. 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| **D1 hooks 范围** | 仅 #1 SessionStart / #2 UserPromptSubmit / #5 SubagentStop 三个轻量 hook | #3/#4/#6 三个写入/拦截类 hook 复杂度高（性能 / 与 /mpdev:* 重叠 / opt-in 机制），推到 v2.2+ |
| **D2 输出形态** | 按 hook 分：#1 additionalContext / #2 systemMessage / #5 additionalContext | #1 #5 是给 Claude 的隐式上下文（用户不可见）；#2 是给用户的明示建议（systemMessage） |
| **D3 禁用机制** | 环境变量 `MPDEV_NO_HOOKS=1` 一开关 | 简单；CI / 噪声敏感场景一行 export 解决；不引入 yaml 配置文件 |
| **D4 跨平台** | 仅 bash 脚本，Windows 用户走 Git Bash | 跟随 mppm 模式；PowerShell 等价 .ps1 hook 推到后期（Claude Code 实测后） |
| **D5 共享工具** | 单文件 `hooks/_lib.sh` 提供 MPDEV_NO_HOOKS check / project root / parse YAML | 3 个 hook 复用同套 30 行工具，避免 3 处重复 |
| **D6 SubagentStop 字段名** | 假设 `subagent_response` 或 `output`，实施时**先实测**确认 | Claude Code SubagentStop event payload schema 未官方文档化；hook 第一次跑要 debug-log 确认 |

## 6. _lib.sh 共享工具

```bash
#!/usr/bin/env bash
# hooks/_lib.sh — 共享工具，被 3 个 hook source

# 用户禁用 → 立即返回 {} 并 exit 0
check_disabled() {
  if [ -n "$MPDEV_NO_HOOKS" ]; then
    echo "{}"
    exit 0
  fi
}

# 找项目根（Claude Code 注入 CLAUDE_PROJECT_DIR；fallback 到 PWD）
get_project_dir() {
  echo "${CLAUDE_PROJECT_DIR:-$PWD}"
}

# 从文件提取 YAML frontmatter 块（首个 --- ~ --- 之间）
extract_frontmatter() {
  awk '/^---$/{c++; next} c==1{print} c==2{exit}' "$1"
}

# 从 frontmatter / markdown 抽取指定 key 的值
get_yaml_field() {
  local content="$1"
  local key="$2"
  echo "$content" | grep -E "^${key}:" | head -1 | sed -E "s/^${key}:[[:space:]]*//; s/^['\"]//; s/['\"]$//"
}

# 安全 JSON 字符串转义（避免破坏 hookSpecificOutput）
escape_json() {
  # 用 jq 处理；jq 不可用时退回最小转义
  if command -v jq >/dev/null 2>&1; then
    echo -n "$1" | jq -Rs .
  else
    # 退化：仅转义 " 和 \
    echo -n "$1" | sed 's/\\/\\\\/g; s/"/\\"/g; s/$/\\n/' | tr -d '\n'
    echo -n '"'
    echo
  fi
}
```

## 7. session-start.sh 完整实现

```bash
#!/usr/bin/env bash
# session-start.sh — mpdev SessionStart hook
#
# 触发: Claude Code 启动 / 新会话
# 输入: stdin {}
# 输出: hookSpecificOutput JSON with additionalContext
# 失败策略: 任何错误都退回 {}，绝不阻塞会话

set -e

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
source "$SCRIPT_DIR/_lib.sh"

check_disabled

PROJECT_DIR=$(get_project_dir)

# Glob CLAUDE.md 排除明显非业务目录
mapfile -t CLAUDE_FILES < <(find "$PROJECT_DIR" \
  -name CLAUDE.md \
  -not -path '*/node_modules/*' \
  -not -path '*/.git/*' \
  -not -path '*/.claude/plugins/*' \
  -not -path '*/target/*' \
  -not -path '*/dist/*' \
  -not -path '*/build/*' \
  2>/dev/null)

# 0 个 → 静默退出
[ ${#CLAUDE_FILES[@]} -eq 0 ] && { echo "{}"; exit 0; }

# 超过 5 个 → 取前 5
COUNT_TOTAL=${#CLAUDE_FILES[@]}
[ $COUNT_TOTAL -gt 5 ] && CLAUDE_FILES=("${CLAUDE_FILES[@]:0:5}")
COUNT_INCLUDED=${#CLAUDE_FILES[@]}

# 拼接摘要
summary=""
for f in "${CLAUDE_FILES[@]}"; do
  rel="${f#$PROJECT_DIR/}"
  module=$(basename "$(dirname "$f")")
  # 提取 "## 技术栈" 节（限 10 行）
  tech=$(awk '/^## 技术栈/{f=1;next} /^## /{f=0} f' "$f" | head -10)
  if [ -n "$tech" ]; then
    summary+="### ${module} (${rel}):\n${tech}\n\n"
  else
    summary+="### ${module} (${rel}): (无 '技术栈' 节)\n\n"
  fi
done

# 构造 additionalContext
omitted=""
[ $COUNT_TOTAL -gt $COUNT_INCLUDED ] && omitted="（还有 $((COUNT_TOTAL - COUNT_INCLUDED)) 个 CLAUDE.md 未注入，按需用 /mpdev:understand 重新理解）"

context="## mpdev: 检测到 ${COUNT_INCLUDED} 个模块 CLAUDE.md ${omitted}

${summary}
（可调 /mpdev:understand 重新生成或更新；/mpdev:dev 启动跨模块开发主流程。）"

# 输出 JSON（用 jq 安全转义）
if command -v jq >/dev/null 2>&1; then
  jq -n --arg ctx "$context" '{
    hookSpecificOutput: {
      hookEventName: "SessionStart",
      additionalContext: $ctx
    }
  }'
else
  # 退化：手动构造 JSON（最小转义）
  esc_ctx=$(echo "$context" | sed 's/\\/\\\\/g; s/"/\\"/g; s/$/\\n/' | tr -d '\n')
  echo "{\"hookSpecificOutput\":{\"hookEventName\":\"SessionStart\",\"additionalContext\":\"$esc_ctx\"}}"
fi
```

## 8. inject-keyword-hint.sh 完整实现

```bash
#!/usr/bin/env bash
# inject-keyword-hint.sh — mpdev UserPromptSubmit hook
#
# 触发: 用户提交 prompt
# 输入: stdin JSON with .prompt
# 输出: hookSpecificOutput with systemMessage (命中时) 或 {} (未命中)

set -e

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
source "$SCRIPT_DIR/_lib.sh"

check_disabled

# 读 stdin → .prompt
if command -v jq >/dev/null 2>&1; then
  PROMPT=$(cat | jq -r '.prompt // ""')
else
  # 退化：grep .prompt 字段
  PROMPT=$(cat | grep -oP '"prompt":\s*"\K[^"]*' | head -1)
fi

# 已在用 /mpdev:* 命令 → 跳过自我推荐
if echo "$PROMPT" | grep -qE '^/mpdev:'; then
  echo "{}"
  exit 0
fi

# 关键词模式表
declare -A PATTERNS=(
  ["修.*bug|fix.*bug|NPE|空指针|异常|报错|stacktrace"]="fix"
  ["新.*需求|新功能|增加.*字段|加.*接口|加.*表|新.*API"]="dev"
  ["理解.*项目|新项目|没有 CLAUDE|代码不熟|看不懂"]="understand"
  ["启动.*服务|起.*环境|环境.*状态|重启.*服务"]="env"
  ["写.*测试|加.*测试|测试覆盖|test case"]="test"
  ["检查.*契约|跨模块.*一致|联调|契约.*漂移"]="check"
  ["生成 commit|提交.*说明|改了什么|commit message"]="commit"
)

for pattern in "${!PATTERNS[@]}"; do
  if echo "$PROMPT" | grep -qE "$pattern"; then
    cmd="${PATTERNS[$pattern]}"
    msg="💡 检测到与 \`/mpdev:${cmd}\` 相关的关键词。如果想用 mpdev 工作流处理，可以试试：

\`\`\`
/mpdev:${cmd} <补充信息>
\`\`\`

（继续当前对话不受影响）"
    if command -v jq >/dev/null 2>&1; then
      jq -n --arg msg "$msg" '{
        hookSpecificOutput: {
          hookEventName: "UserPromptSubmit",
          systemMessage: $msg
        }
      }'
    else
      esc_msg=$(echo "$msg" | sed 's/\\/\\\\/g; s/"/\\"/g; s/$/\\n/' | tr -d '\n')
      echo "{\"hookSpecificOutput\":{\"hookEventName\":\"UserPromptSubmit\",\"systemMessage\":\"$esc_msg\"}}"
    fi
    exit 0
  fi
done

echo "{}"
```

## 9. post-subagent-check.sh 完整实现

```bash
#!/usr/bin/env bash
# post-subagent-check.sh — mpdev SubagentStop hook
#
# 触发: subagent 跑完
# 输入: stdin JSON; 假设 .subagent_response 或 .output 含输出文本
# 输出: hookSpecificOutput with additionalContext (cross_module_issue 命中) 或 {}

set -e

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
source "$SCRIPT_DIR/_lib.sh"

check_disabled

# 读 stdin → subagent 输出文本
if command -v jq >/dev/null 2>&1; then
  RESPONSE=$(cat | jq -r '.subagent_response // .output // .response // ""')
else
  RESPONSE=$(cat)
fi

# 提取 cross_module_issue 字段
ISSUE=$(echo "$RESPONSE" | grep -E 'cross_module_issue:[[:space:]]*[^[:space:]n]' | head -1)
[ -z "$ISSUE" ] && { echo "{}"; exit 0; }

# null / "" 值 → 跳过
echo "$ISSUE" | grep -qE 'cross_module_issue:[[:space:]]*(null|""|\b\s*$)' && { echo "{}"; exit 0; }

# 解析 value
DESC=$(echo "$ISSUE" | sed -E 's/cross_module_issue:[[:space:]]*//; s/^"//; s/"$//; s/^[[:space:]]*//')

# 启发式抽模块名
TARGET=$(echo "$DESC" | grep -oE '\b(java|vue|dispatch|analytics|algor|h5|pad|web|frontend)\b' | head -1)

# 构造 additionalContext
if [ -n "$TARGET" ]; then
  suggestion="\n\n建议下一步：\`/mpdev:fix ${TARGET} <bug 描述>\`"
else
  suggestion="\n\n建议检查 cross_module_issue 涉及的模块，跑 \`/mpdev:fix <module> <bug>\`。"
fi

context="## 跨模块影响提示

上一步 impl agent 反馈跨模块影响：
> ${DESC}
${suggestion}"

if command -v jq >/dev/null 2>&1; then
  jq -n --arg ctx "$context" '{
    hookSpecificOutput: {
      hookEventName: "SubagentStop",
      additionalContext: $ctx
    }
  }'
else
  esc_ctx=$(echo "$context" | sed 's/\\/\\\\/g; s/"/\\"/g; s/$/\\n/' | tr -d '\n')
  echo "{\"hookSpecificOutput\":{\"hookEventName\":\"SubagentStop\",\"additionalContext\":\"$esc_ctx\"}}"
fi
```

## 11. install.sh / install.ps1 chmod 处理

hook 脚本必须可执行。install.sh / install.ps1 末尾在 BOM 自检之前（或之后）追加：

```bash
# install.sh
chmod +x "$TARGET/hooks/"*.sh 2>/dev/null || true
chmod +x "$TARGET/hooks/_lib.sh" 2>/dev/null || true
```

```powershell
# install.ps1
# Windows 上 chmod 是 noop（NTFS 没 +x 位）；Git Bash 在 Windows 上跑 hook 会用 .sh shebang
# 此节为 Mac/Linux 用户保留
```

实际上 install.ps1 不做 chmod（Windows 文件系统不需要），但需要保证 .sh 文件本身有 unix LF 行尾（不是 CRLF）。可以在 install.ps1 加一段：

```powershell
# 确保 .sh 文件用 LF 行尾（防 git autocrlf 转 CRLF 后 bash 解析失败）
foreach ($f in (Get-ChildItem -Path "$Target/hooks" -Filter '*.sh').FullName) {
    $content = [System.IO.File]::ReadAllText($f) -replace "`r`n", "`n"
    [System.IO.File]::WriteAllText($f, $content, [System.Text.UTF8Encoding]::new($false))
}
```

| 关键词模式误命中（代码片段含 "异常"）| 中 | 低 | 模式正则严格化（要求"修"/"fix"/动词前缀）；`/mpdev:` 开头跳过；MPDEV_NO_HOOKS 兜底 |
| Glob CLAUDE.md 在大仓极慢 | 低 | 低 | `find -not -path` 排除 node_modules/.git/target/dist/build；timeout: 5 兜底 |
| hooks.json schema 出错 | 低 | 高 | install.sh / install.ps1 末尾跑 `jq -e empty hooks.json` 校验；失败 warn 不阻塞但显眼提示 |
| jq 不可用（极少数最小化系统） | 极低 | 低 | 所有 hook 退化用 grep/sed（jq 路径优先） |
| install.ps1 把 .sh 文件 CRLF 转 LF 失败 | 低 | 中 | 加 try/catch，失败 warn；用户可手动 dos2unix |
